# 2P 테스트 커맨드 입력

## 사용 방법

1. `Assets/QuantumUser/Resources/LSDF_Player2TestInput.asset`을 선택한다.
2. Inspector의 **2P 테스트 입력 사용**을 켠다. 초기값은 꺼져 있다.
3. **방향**과 **공격 버튼**을 선택한다. 예: `앞+아래 (↘)` + `RP · 오른손 (I)`.
4. 2P로 접속한 Editor 또는 Development Build에서 자동 입력한다. 1P는 평소처럼 키보드로 조작한다.

| 설정 | 의미 | 초기값 |
|---|---|---|
| 방향 | 중립 / 뒤 / 뒤+아래 / 아래 / 앞+아래 / 앞 / 위. 캐릭터 기준 방향 | 중립 |
| 공격 버튼 | LP / RP / LK / RK | LP |
| 반복 입력 | 켜면 주기적으로, 끄면 한 번 입력 | 켜짐 |
| 시작 대기 (틱) | 라운드 조작 잠금이 풀린 뒤 첫 입력까지 대기 | 30 |
| 반복 간격 (틱) | 입력 시작과 다음 입력 시작 사이의 틱 수 | 120 |
| 누르고 있는 시간 (틱) | 각 입력에서 방향과 공격을 함께 유지하는 틱 수 | 1 |

현재 세션 기본 60틱은 1초다. 초기값은 조작 가능 후 약 0.5초 대기, 2초마다 한 번 입력한다.
반복 간격이 누름 시간보다 짧아도, 버튼을 놓는 틱을 최소 1틱 보장한다.
입력하지 않는 틱에는 방향과 공격을 모두 놓는다. 이동이나 앉기를 계속 유지하려는 설정은 아니다.
입력을 시도할 당시 경직/공격 중이면 기존 커맨드 버퍼와 상태 제약이 그대로 적용된다.

실행 기술은 **2P가 해당 커맨드에 배합한 기술**이다. 이 설정은 커맨드를 보내며 로드아웃은 변경하지 않는다.
카운터 줌 테스트 예: 2P에 발동이 느린 기술의 커맨드를 반복 입력시키고 1P의 공격으로 발동 전에 끊는다.
테스트를 끝내면 **2P 테스트 입력 사용**을 끄면 된다. 다음 입력 폴링부터 키보드 조작으로 돌아간다.

플레이 도중 방향/버튼/시간/반복 설정을 바꾸면 대기를 처음부터 다시 계산한다. 라운드 잠금이나 KO 중에는
자동 입력을 중립으로 두며, 다음 라운드 조작 잠금이 풀리면 다시 시작한다. `반복 입력`을 끈 경우에도 라운드마다 한 번이다.

## 연결과 경계

- 게임플레이 씬의 기존 `LSDF_PlayerInput.Player2TestInput`에 설정 에셋을 연결했다.
- `CallbackPollInput.PlayerSlot`은 로컬 슬롯이므로 2P 번호로 해석하지 않는다.
  설치된 Quantum 3의 `Session.TryGetLocalPlayer(PlayerSlot, out PlayerRef)`로 실제 플레이어를 확인하고 전역 `(PlayerRef)1`에만 적용한다.
- 입력 구독은 `ViewUpdater.ObservedGame`에 한정한다. 1P 창에서 원격 2P를 대신 조종하지 않는다. 2P가 동작하는 창에 설정이 켜져 있어야 한다.
- 같은 컴퓨터에 로컬 플레이어가 여러 명이어도 1P 폴링이 2P의 반복 스케줄을 초기화하지 않는다.
- Editor / Development Build에서만 입력 덮어쓰기 코드를 컴파일한다. 일반 릴리스 빌드에서는 키보드 입력을 사용한다.
- 자동 입력은 기존 `CallbackPollInput.SetInput`으로 전송한다. Frame, Animator, 로드아웃과 판정 코드는 수정하지 않는다.
  재생·관전자 모드에는 자동 입력을 적용하지 않는다. 재생은 기록된 입력을 사용한다.
- 스케줄의 기준은 입력 폴링 틱이며 Unity deltaTime이 아니다. 동일 스케줄/설정/틱은 같은 입력을 만든다.
  스케줄은 입력을 생산하는 로컬 View 상태이고, 생성한 입력이 Quantum 기록·동기화 대상이 된다.
- 비활성화/재활성화, Game 변경, 설정 에셋 교체 시 입력 스케줄을 초기화한다. 구독을 중복 등록하지 않는다.
