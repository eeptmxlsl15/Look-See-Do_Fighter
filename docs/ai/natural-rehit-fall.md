# 2·3·4타 이후 자연스러운 공중 낙하

## 사용자 증상과 원인

첫 시동기만 맞으면 원래 중력으로 내려오지만, 실제 공중 후속타를 맞으면 여전히
`Returning → SlowFalling`에서 일정 하강 속도가 갑자기 다른 일정 속도로 바뀌었다.
추가타를 멈춰도 착지까지 같은 속도로 내려가는 경로가 남아 있었다.
사용자 보고와 해당 소스 분기를 근거로 수정했다. 수정 전 화면을 자동 재현한 것은 아니다.

## 변경된 동작

- 재타격 시 작은 상승 → Combo Height로 복귀 → 기준 높이 아래 저속 낙하는 유지한다.
- 복귀는 정점의 접선 속도 0과 기준 높이의 낙하 시작 속도를 잇는 FP cubic Hermite 곡선으로 바꿨다.
  다음 물리 틱의 곡선 위치에 맞는 속도를 계산하고 실제 Transform 위치는 순간 이동시키지 않는다.
- 기준 높이 아래에서는 시작 속도에 일정 가속도를 더한다. 속도는 경과 틱으로 계산하므로
  같은 틱을 중복 처리해도 더 빨라지지 않고 재타격마다 동일한 낙하가 시작된다.
- 추가 상승 높이가 작고 시작 속도가 큰 조합은 끝 접선을 제한해 복귀 도중 기준 높이 아래로
  먼저 지나쳤다가 올라오는 현상을 막는다. 추가 상승이 0이면 시작 속도도 0에서 가속한다.
- 시동기 단독 원래 중력 낙하, 시동기 제외 후속타 5회 제한, 지정 마무리, 밀림, 벽·착지·KO·라운드 초기화는 유지한다.

## 설정

`Assets/QuantumUser/Resources/LSDF_GameConfig.asset → Air Combo`:

| Inspector 항목 | 현재 값 | 역할 |
|---|---|---|
| 기준 높이 아래 낙하 시작 속도 | 0.2 | 기준 높이에 도착할 때의 하강 속도. 기존 `SlowFallSpeed` 직렬화 필드 유지 |
| 기준 높이 아래 낙하 가속도 | 0.1 | 기준 높이 아래에서 서서히 빨라지는 정도. 낮출수록 더 오래 체공하며 0은 일정 속도 |

기존 높이, 상승/복귀 6틱, 처음 체공 30틱, 사용자 밀림 0.1 등은 보존했다.
새 가속도는 불변 게임 설정이며, 경과 틱은 기존 Frame 컴포넌트의 `HoldUntilTick`에서 계산한다.
이번 수정에 QTN 필드 추가와 CodeGen은 필요하지 않았다. 작업 시작 전부터 존재한 QTN/생성 코드 변경은 보존했다.
물리/Player/Animator/히트박스 생성·파괴 시스템 순서는 바꾸지 않았다.
다른 낙하 규칙의 클라이언트와 분리하도록 매칭 프로토콜을 `lsdf-loadout-v10-natural-rehit-fall`로 올렸다.

## 검증 범위와 결과

구현 후 한 차례 묶음: 정적 정책, diff 공백, Unity 컴파일, 공중 궤적/1~4 후속타 뒤 중단·착지/
동일 낙하/마무리·전투 단위 회귀, 두 실제 Photon 클라이언트, 입력 재생 2회와 낙하 중 Frame 복원.
마무리 전용 온라인 fixture는 타수/종료 규칙을 분리하기 위해 가속도 0을 사용한다.
낙하 전용 온라인 fixture는 새 기본 가속도 0.1을 사용한다. 설정은 세션 시작 전 메모리에서만 변경하고 종료 후 복원한다.

최종 결과는 `evidence/natural-rehit-fall-validation.json`에 기록한다.
실제 화면의 자연스러움은 사용자 플레이 평가가 필요하다. 자동 물리 궤적/체크섬 검사는 화면 평가,
다른 플랫폼 결정론, 강제 네트워크 지연에 의한 rollback의 증거로 바꾸어 표현하지 않는다.
