# 체력바 배경과 채움 크기 보정

기준: `dev/Prototype`, `b40aea428812a98bb9d516e32434d5db5329fd51`. 후속 UI 버그 수정.

## 원인

사용자가 연결한 atlas의 배경 Sprite는 529×105, 채움은 436×40인데 이전 표시 코드는 각각 같은 800×70 RectTransform에 늘려 그렸다.
채움이 배경의 테두리까지 덮고 두 그림의 종횡비도 달라졌다. PNG 해상도나 HP 계산의 문제가 아니다.
열린 LSDFGameplay는 사용자 미저장 변경이 있는 상태였다. 현재 연결/크기/원본 Sprite 정보를 읽고 기존 작업을 보존했다.

## 수정과 조절

[게임 UI 설정](../../Assets/QuantumUser/View/LSDFSceneBindings.GameplayUI.cs)의 체력바 항목에 다음을 추가했다.

- **체력바 원본 비율 자동 맞춤**: 기본 켬. 배경 너비를 기준으로 원본 종횡비를 맞추고 채움을 배경 중앙에 배치한다.
- **체력바 가로 크기**: 0은 기존 너비 유지. 양수면 양쪽 HUD에 같은 너비를 적용한다.
- **체력 채움 크기 배율**: 기본 (1, 1). 원본 배경 대비 채움의 가로/세로 비율에 곱하며 배경 크기를 넘지 않게 제한한다.
- **체력 채움 위치 보정**: 기본 (0, 0). 배경 중심 기준 Canvas 단위로 이동한다.

현재 너비 800에서는 배경이 약 800×158.79, 채움은 약 659.36×60.49가 된다.
`LSDFSceneBindings → 게임플레이 UI 이미지 → 체력바`에서 조절한 뒤 기존 적용/미리보기 버튼을 쓴다.
Sprite 절단/투명 여백 때문에 남는 차이는 크기 배율과 위치 보정으로 맞출 수 있다.
자동 맞춤을 끄면 기존 RectTransform 수동 배치를 유지한다.

Image의 원본 Sprite·GUID/잘라낸 rect·HP fillAmount/좌우 fillOrigin을 보존하고, 두 Image가 속한 기존 흔들림 부모를 바꾸지 않는다.
현재 프로젝트의 두 이미지가 같은 부모에 있는 HUD에만 자동 배치를 적용한다. 참조/이미지가 없거나 서로 다른 부모라면 기존 배치를 유지한다.
배경과 채움의 픽셀 크기 비율은 동일한 그림 밀도로 제작된 아트를 기준으로 한다. 다른 배율의 아트는 Inspector의 채움 배율로 조절한다.
Simulation/QTN/SDK/승패/피해/프로토콜 변경은 없다. PNG 픽셀과 사용자의 atlas 메타는 수정하지 않는다.
