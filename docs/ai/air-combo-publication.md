# 공중 콤보 변경 게시 기록

사용자가 게임 테스트를 모두 완료했다고 알리고 현재 결과의 Push를 요청했다.
이 요청에 따라 게임 컴파일/실행 테스트를 자동 반복하지 않고 사용자 검증 완료 통보를 별도 근거로 기록한다.
이전 자동 검사 실패와 fixture 수정 후 미검증 기록은 그대로 보존한다.
사용자 수동 검증의 세부 시나리오/환경이나 온라인 재생 통과 로그를 새로 확보한 것으로 표현하지 않는다.

## 현재 게시 내용

- 시동기 피격 이후 상승/체공/낙하를 Frame 상태로 관리한다.
- 일반 공중 후속타마다 시동기 기준 고정 높이로 즉시 복귀하고 세로 속도를 0으로 초기화한다.
- 시동타는 제외하고 후속타 5회째에 날린다. 지정한 마무리 기술은 순번과 관계없이 날린다.
- 날아가는 동안과 착지 후 회복 중 추가타를 차단하고 벽/착지/KO/라운드 수명을 정리한다.
- 사용자 현재 설정: 첫 체공 30틱, 재타격 체공 30틱, 공중 밀림 속도 약 0.1/6틱.
- 사용자 2P 테스트 설정: 시작 대기 0틱, 입력 간격 1틱. 현재 설정을 함께 보존한다.
- 매칭 버전은 `lsdf-loadout-v7-fixed-juggle`이며 QTN과 설치 CodeGen 산출물/meta 짝을 포함한다.

## 검증 근거 구분

기존 자동 검사: 컴파일 오류 0, 단위/회귀 84개 통과, 온라인 시나리오 2개 실패.
온라인 fixture의 중립 RP 입력을 실제 Law 어퍼 입력(아래앞 RP/17번 슬롯 스킬 1)으로 수정했으며
자동 재실행은 하지 않았다. 상세 기록은 [고정 공중 콤보](fixed-air-combo.md) 및 해당 증거 JSON을 따른다.
이후 체공 시간을 30틱으로 조율한 현재 설정에 대한 검증 완료는 이번 사용자의 통보다.

게시 후보의 비밀정보/불필요 파일 검사와 정적 정책 검사는 게임 테스트와 구별한다.
후보 45개 파일의 비밀정보/불필요 파일 검사와 Simulation 93개 정적 정책 검사는 통과했다.
스테이징 후 전체 후보에서 확인한 생성물 3개 파일의 끝 공백 5건은 기능 변경 없이 보존하며
공백 검사 실패로 보고한다(Core 코드 1, QTN meta 3, View prototype 코드 1).
검사 후 이 게시 기록의 결과 설명만 추가했으며 해당 문구를 수동 검토했다.
IDE 생성 `.csproj`/`.sln` 파일은 게시 후보에 포함하지 않고 작업 트리에 남긴다.

## 게시 대상

기존 저장소 `eeptmxlsl15/Look-See-Do_Fighter`, 원격 `origin`, 작업 브랜치 `dev/Prototype`.
Push 범위의 비교 기준은 최신 fetch한 `origin/dev/Prototype`이다. PR 생성은 요청 범위에 없다.
정확한 로컬 커밋을 만든 뒤 해당 SHA와 함께 Push 승인을 받는다.
