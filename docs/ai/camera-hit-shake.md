# 피격 시 전체 카메라 흔들림 — 2026-10-19

누가 맞든 로컬 게임 화면을 짧게 좌우·상하로 흔든다. 기존 카운터 줌과 피격 체력바 흔들림은 함께 재생한다.

## 설정과 동작

`Assets/Scenes/LSDFGameplay.unity`의 `EntityViewUpdater → LSDFSceneBindings`에서 조절한다.

- `HitShakeDuration`: 기본 **0.18초**.
- `HitShakeStrength`: 기본 **0.015 월드 단위**. 두 값 중 하나를 0으로 두면 카메라 흔들림을 끈다.
- 양쪽 플레이어의 VerifiedFrame HP 감소 또는 새 피격 상태/DelayFrame 변화를 감지한다. 가드만으로는 발동하지 않는다.
  피해 0 피격도 새 피격 상태로 감지한다. 최초 연결 프레임은 기준점으로만 사용한다.
- 같은 확정 tick을 반복해서 읽어도 재발동하지 않으며 연타/동시 피격은 한 카메라의 흔들림 시간을 다시 시작한다.
- 평상시 추적 → 기존 카운터 줌 → 화면축 흔들림 순서로 합성한다. 카메라 회전/렌즈는 흔들림이 변경하지 않는다.
  이전 흔들림을 제거한 위치로 다음 연출을 계산하므로 연타에도 위치가 누적되지 않는다.
- 기존 체력바 코드/프리팹/강도와 카운터 줌 설정 에셋/기술 선택을 유지한다.
- Game/카메라/엔티티 변경, 로컬 시점 소실, 비활성화, 회복/인트로, 과거 확정 tick에서 정리한다.
  KO의 짧은 흔들림은 결과 화면 중에도 끝까지 재생할 수 있다.
- View 전용 상태와 Unity 시간만 사용하며 Simulation/QTN/CodeGen/시스템 순서/판정은 바꾸지 않는다.
  확정 프레임 감지라서 네트워크 확정 지연은 남는다. 별도의 예측 이벤트 구독을 추가하지 않는다.

## 최종 한 차례 검증

Unity 컴파일, 새 카메라 사례와 기존 카운터 줌/체력바·씬 연결 회귀, 정적 정책, 변경 공백·메타/문서 링크를 한 묶음으로 실행한다.
화면 감각의 육안 평가와 실제 Photon 온라인 플레이·강제 지연 rollback은 이 View 검사와 구분한다.

| 카메라 흔들림·기존 줌·체력바 회귀 | **20 PASS / 3 FAIL / 0 SKIP**, 23개, 0.98초. 아래 실패 내용 참조 |

기존 기상 콜라이더의 온라인 실패·수정 후 미검증 상태는 [현재 작업 상태](current-state.md)에 유지한다.

체력바·HUD 회귀 4개 중 4개가 통과했다. 양쪽 시점/양쪽 피격, 원위치 복구, 반복 tick/연타,
피해 0/가드/회복/되감기/0 설정, 이동 중인 줌·체력바와의 동시 재생, 실제 씬 연결이 통과했다.

기존 줌 체크리스트 검사 1개는 현재 사용자가 선택해 둔 기술이 있는데도 전체 비활성 상태를 요구했다.
실패 후 테스트만 보정했다. 수명 검사는 OnDisable/OnEnable을 명시적으로 호출하고,

실제 줌 에셋의 체크/수치나 카메라·체력바 런타임 코드는 이 검사 후 변경하지 않았다.

사용자 단일 검증 방침에 따라 재검사하지 않았으므로 **테스트 코드 수정 후 미검증**이다.
실패를 포함한 원본 결과와 검사 전/수정 후 소스 해시는 [검증 근거](evidence/camera-hit-shake-validation.json)에 보존한다.
보정한 테스트 파일은 공백 검사도 재실행하지 않았다. 커밋·Push는 하지 않았다.
