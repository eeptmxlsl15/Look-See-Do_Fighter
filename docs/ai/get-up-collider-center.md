# 기상 애니메이션의 콜라이더 위치 설정

## 사용법

`Assets/QuantumUser/Resources/LSDF_GameConfig.asset → Air Combo → 일어날 때 콜라이더 위치`에서
누워 있다가 일어나는 애니메이션의 콜라이더 중심을 따로 조절한다.

- 기본 **X 0 / Y 0.01**, 엔티티 원점에 대한 월드축 오프셋이다.
- X가 커지면 오른쪽, Y가 커지면 위쪽이다. 양쪽 플레이어에서 X를 자동 반전하지 않는다.
- 실제 기상 애니메이션 `Rising`의 시작부터 종료·중단까지 적용한다.
  공중 콤보의 첫 상승 단계 `LSDFAirComboPhase.Rising`과는 별개다.
- 기상이 끝나면 현재 서기/앉기 중심으로 돌아간다. 새 날리기, 공중 피격, KO·라운드 종료 때도 이전 기상 중심이 남지 않는다.
- 크기와 스프라이트 위치는 직접 바꾸지 않는다. `날아갈 때 콜라이더 위치`와 독립된 값이다.

작업 시작 시 사용자가 조정한 날리기 중심 **Y 0.2**, 낙하 시작 속도 **0.3**, 낙하 가속도 **0.5**는 보존했다.
새 항목만 기존 서 있는 중심과 같은 기본값으로 직렬화했다.

## 구현과 수명

`LSDFJuggleSettings.GetUpColliderCenter`는 불변 설정이다.
Quantum Frame의 Animator 기본 레이어 상태를 읽고, 실제 `RisingWindowEvent.OnEnter/OnExit`에도
중심 갱신을 연결해 시작·종료 시점의 이전 중심이 남지 않게 했다.
위치 갱신은 Frame의 `PhysicsCollider2D`에 쓰며 Unity Animator/Transform이나 공유 이벤트 에셋에 상태를 저장하지 않는다.
프레임 간 상태는 기존 Animator/Player/AirCombo 컴포넌트로 충분하므로 새 QTN 필드와 CodeGen은 필요하지 않다.

회복 중에는 기상 상태의 오래된 표시보다 기존 종료 회복 규칙이 우선하고, 새 날리기는 기상 설정보다 날리기 설정이 우선한다.
콜라이더 갱신의 불필요한 Body 포인터 의존도 제거했다. 라운드 초기화가 Entity만 가진 부분 Filter로 호출해도
Frame에서 필요한 컴포넌트를 조회하므로 미지정 Body 포인터를 역참조하지 않는다.

이전 요청의 PlayerSystem 내부 `Juggle → Collider` 순서는 보존한다.
시스템 등록/Physics→Player→Animator/명령/히트박스 수명과 에셋·타입명·상태명·GUID는 바꾸지 않는다.
이전 상태에서 아직 미검증이던 착지 보정도 이번 요청의 기상 연결과 함께 최종 한 차례에 포함한다.
기상 충돌 설정을 구버전과 섞지 않도록 프로토콜을 `lsdf-loadout-v12-get-up-collider-center`로 구분한다.

## 최종 한 차례 검증

정적 정책, diff 끝 공백, Unity 컴파일, 콜라이더·공중·마무리·라운드 단위 회귀를 실행한다.
콜라이더 검사는 별도 기상 중심/종료 후 서기·앉기 복구/새 피격·날리기 우선/KO·라운드 종료/두 엔티티 격리를 포함한다.

실제 Photon 마무리 fixture에서 세션 시작 전 메모리로만 다음 값을 지정한다.

| 상태 | X | Y |
|---|---|---|
| 날리기 | 0.02 | -0.05 |
| 기상 | 약 0.03 | 0.02 |
| 기본 서기·회복 | 0 | 0.01 |

양쪽 관측자에서 5후속타 종료·조기 마무리 → 착지 회복 → 기상 → 기본 자세의 실제 콜라이더 중심을 관측한다.
확정 프레임 체크섬과 입력 재생 2회, 날리기 중/기상 중 Frame 복원 후 재시뮬레이션을 비교한다.
fixture는 세션 종료 후 에셋을 복구하고 파일은 저장하지 않는다.

결과는 `evidence/get-up-collider-center-validation.json`에 기록한다.
자동 시나리오는 실제 화면의 시각적 중심 평가·임의 지형·독립 빌드/교차 플랫폼/강제 네트워크 지연 rollback과 구별한다.
이전 요청의 실패 기록은 `ender-collider-center-validation.json`에 보존하며 새 결과로 덮어쓰지 않는다.

| 한 차례 검증 결과 | 상태 |
|---|---|
| 정적 정책 / diff 끝 공백 | PASS — 최종 착지 보정 전, Simulation 93개 파일 신규 적중 0 |
| Unity 컴파일 | PASS — 최종 착지 보정 전, 오류 0·기존 경고 9건 |
| 단위 회귀 | PASS — 콜라이더 23, 공중 36, 마무리 21, 라운드 19 = 99개 |
| 실제 Photon 2클라이언트 시나리오 | FAIL — 첫 구간 5타 종료 관측, 회복 0틱·복구 False |
| 온라인 기상 완료·체크섬 최종 비교·재생·Frame 복원 | NOT RUN — 위 실패로 완료 단계에 도달하지 못함 |

job `56fa719d17704e89823469a8ec2d9cea`: **100개 중 99 PASS / 1 FAIL / SKIP 0**.
이전 순서 변경만으로 온라인 착지 문제가 해결됐다고 볼 수 없다.
실패 후에는 초기 1틱의 상승 접촉을 보호하면서 이후 바닥 접촉은 물리 반동으로 세로 속도가 양수여도 회복을 시작하도록
착지 조건을 보정했다. 회복 진입 시 반동 속도도 0으로 정리했다. 관련 회귀 사례를 추가했으나 실행하지 않았다.
이는 기존 착지 조건에서 확인한 원인 후보에 대한 수정이며 실패 프레임의 실제 반동 속도를 직접 관측한 결과는 아니다.
사용자 방침에 따라 자동 재검사하지 않아 **최종 수정 후 미검증**이다. 검사 전/수정 후 소스 해시는 별도 기록했다.
커밋·Push는 하지 않았다.
