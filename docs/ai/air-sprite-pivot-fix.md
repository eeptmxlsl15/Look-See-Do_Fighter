# 공중 콤보 중단 후 화면상 재상승 — Air 스프라이트 기준점 수정

## 확인된 원인

사용자는 5타 이전에 공격을 멈추면 내려오던 캐릭터가 약간 다시 올라가는 느낌이 남는다고 보고했다.
이전 수정은 Quantum 좌표의 낙하만 검사하고 공중 스프라이트의 기준점(pivot)을 검사하지 않았다.

실제 `Air.anim`과 `Air_Enemy.anim`은 각 60프레임 반복 애니메이션이다.
두 방향 모두 이미지 캔버스는 69×52, PPU는 100으로 일정하지만 pivot Y가 다음처럼 달랐다.

| 프레임 | 기존 pivot Y |
|---|---|
| 1~30 | 0.6 |
| 31~35 | 0.65 |
| 36~40 | 0.7 |
| 41~45 | 0.75 |
| 46~56 | 0.8 |
| 57 / 58 / 59 / 60 | 0.85 / 0.9 / 0.95 / 1.0 |

60→1 반복 시 그림 기준점이 20.8픽셀, 월드 단위로 **0.208**만큼 바뀐다.
실제 엔티티가 계속 내려와도 그림은 위로 튈 수 있다. 느린 공중 콤보 낙하는 1초를 넘어 반복 경계를 지나므로
단독 시동기 낙하보다 문제가 잘 드러난다. 실제 사용자 화면의 녹화 재현과는 구별하며, 이 수치는 소스·import 설정 근거다.

## 수정 범위

플레이어/상대방 공중 이미지 31~60번, 총 60개 `.png.meta`의 single-sprite pivot만 첫 프레임과 같은 `(0.5, 0.6)`으로 맞췄다.
이미지 픽셀·크기·PPU·GUID·클립의 프레임 순서·애니메이션 이벤트·반복 여부는 그대로다.
원래의 자세 변화는 유지하고 pivot으로 더해지던 별도 낙하와 반복 시 재상승을 없앤다.

이번 요청에서 실제 Simulation/Config/QTN/View 소스의 동작은 변경하지 않았다.
조사 중 검토한 낙하 곡선 변경은 적용하지 않고 작업 시작 시점으로 되돌렸다.
이전 공중 콤보·설정·IDE 파일 변경은 보존했다. 새 매칭 버전이나 CodeGen은 필요하지 않다.

## 한 차례 최종 검증

- Unity 재임포트/컴파일 및 기존 콘솔 확인.
- 실제 클립이 참조하는 60개 Sprite의 import 결과에서 캔버스 크기·월드 기준점 일치 확인: 플레이어/상대방.
- 기존 FP 공중 궤적 + 실제 clip Sprite 기준점을 함께 사용해 1~4후속타 뒤 중단·착지와 60→1 반복 경계에서
  그림의 캔버스 기준점이 위로 뛰지 않는지 검사: 양쪽 8사례. 같은 픽셀 좌표 기준이며 캐릭터 자세 변화와는 구별한다.
- 기존 공중·마무리 회귀, 정적 정책, diff 공백 확인.

새 검사는 Unity import 결과를 사용하는 EditMode 회귀다. 화면 렌더·온라인 View 재접속·실제 카메라 평가를 대신하지 않는다.
이번 수정에는 결정론적 게임 동작 변경이 없으므로 온라인 체크섬/재생을 재실행하지 않는다.
