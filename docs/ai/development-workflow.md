# 지속 개발과 게임 완성 운영 지침

리팩토링 이후에도 같은 Quantum 3 규칙으로 기능 추가, 버그 수정, 전투 개선, UI/연출과 출시 준비를 진행한다.
이 문서는 작업 방법과 완성 체크리스트다. 여기에 적힌 모든 후보 기능을 지금 자동 구현하라는 지시는 아니다.
재개 시 [현재 작업 상태](current-state.md)와 관련 작업 기록/증거를 먼저 읽고 실제 Git 상태와 소스에 대조한다.

## 자율 작업 원칙

- 사용자가 요청한 기능/수정은 조사 → 구현 → 연결 → 최종 검증 한 차례 → 기록까지 진행한다.
- 일반적인 설계·구현·로컬 파일 변경은 허가를 다시 묻지 않는다. 합리적인 가정과 선택 이유를 결과에 남긴다.
- 필요한 소규모 구조 개선은 기능 구현과 함께 수행한다. 관련 없는 전체 리팩토링으로 작업을 확대하지 않는다.
- 기존 사용자 변경을 보존한다. 외부 서비스 접근이나 도구 실행이 막히면 가능한 로컬 작업을 완료하고 실제 제한을 보고한다.
- 작업 범위 밖의 배포·게시·결제·파괴적 정리는 자동 수행하지 않는다. 문서는 실행 환경의 권한 정책을 변경하지 않는다.

## 작업 종류별 완료 조건

| 종류 | 구현 기준 | 최종 한 차례에서 확인할 것 |
|---|---|---|
| 새 기능 | 플레이어 동작, 상태 전이, 설정/입력/UI까지 연결 | 정상 흐름과 가장 중요한 실패·재진입 조건 |
| 버그 수정 | 증상→원인→최소 수정, 기존 기능 유지 | 원래 문제와 인접 회귀 시나리오 |
| 리팩토링 | 외부 동작 보존, 책임/데이터 경계 개선 | 기존 기록 대비 동작·타이밍 |
| 밸런스 | 바뀔 수치와 게임 의도 명시 | 피해/경직/발동/가드 결과 |
| UI·연출 | View 수명, 로컬 플레이어, 중복 구독 관리 | 양쪽 시점, 재활성화, 표시/취소 |
| 최적화 | 관측된 병목에 한정, 근거 없는 대형 변경 배제 | 고정 조건 측정과 기능 유지 |
| 빌드·완성도 | 재현 가능한 실행·설정·오류 처리 | 실제 빌드 실행 및 핵심 플레이 흐름 |

소스 읽기와 기존 로그 분석은 계속 가능하다. 반복 플레이·테스트로 가설을 무제한 탐색하지 않는다.
실행을 통한 사전 재현이 꼭 필요하면 그것이 이번 작업의 한 차례 검증이 된다.
그 후 패치는 `수정 후 미검증`으로 구분한다. 확인이 부족한 결과를 완료/통과로 포장하지 않는다.

## Quantum 3 기능 배치

| 내용 | 두어야 하는 곳 |
|---|---|
| HP, 승패, 타이머, 쿨다운, 연타 버퍼 | Frame의 컴포넌트/싱글턴/global |
| 공격/캐릭터/매치 규칙 | 불변 AssetObject와 AssetRef |
| 지속적인 플레이어 조작 | Quantum Input, CallbackPollInput |
| 매치 시작 플레이어 설정 | RuntimePlayer → AddPlayer → GetPlayerData |
| 실행 중 일회성 게임 명령 | 필요한 경우 결정론적 Command와 등록 경로 |
| 카메라, HUD, 효과, 사운드, 로컬 저장 UI | Unity View/메뉴, Frame이나 Quantum 이벤트 구독 |

뷰에서 판정 상태를 직접 바꾸거나 PlayerPrefs를 시뮬레이션 입력으로 읽지 않는다.
새 QTN/시스템/에셋은 생성 코드·등록·참조까지 연결한다. SDK/애드온 코어 복사 수정 대신 프로젝트 확장 지점을 먼저 사용한다.

## 게임 완성 마일스톤

현재 달성 여부는 실제 구현과 증거로 판단한다. 아래 항목은 모두 완료했다고 가정하지 않는다.

1. **기반 안정화**: 로드아웃 전달, 고정소수 판정, 엔티티별 실행 상태, 컴파일과 핵심 전투 흐름.
2. **한 매치 완주**: 메뉴 → 스킬 선택 → 연결 → 라운드 시작 → 전투 → 라운드/매치 종료 → 재대전/메뉴 복귀.
   제한시간, 동시 KO, 승패, 입력 잠금, 회복/초기화 규칙을 일관되게 정한다.
3. **전투 완성도**: 이동/대시/앉기/패링, 상중하단, 카운터/런처/벽/연타, 데미지·경직·표시 일치.
4. **네트워크·수명 안정화**: 연결 실패, 이탈/재접속, 중복 생성, 세션 종료, 씬 재진입, 다중 Runner 범위.
5. **사용성·연출**: 조작 안내, HP/라운드/결과 UI, 오디오/VFX, 해상도와 설정 저장, 명확한 실패 안내.
6. **배포 가능한 결과물**: 재현 가능한 빌드, 필수 설정 안내, 알려진 이슈, 플레이 안내, 라이선스/크레딧.
   외부 배포는 사용자가 요청한 경우에만 수행한다.

연습모드, 키 리바인딩, 리플레이 UI, 추가 캐릭터/스테이지 등은 요구가 생겼을 때 별도 기능으로 다룬다.
후속 작업에서 새로운 요구를 추가해도 기존 Quantum 3 상태 소유권과 단일 검증 규칙은 유지한다.

## 작업 기록과 우선순위

결정론/데이터 손상/진행 불가 버그 → 요청된 핵심 플레이 흐름 → 일반 결함 → 연출/편의 순으로 판단한다.
현재 요청과 직접 연결되지 않은 발견은 후속 항목으로 남긴다.
기록에는 문제/기능, 완료 조건, 변경 파일, 결정한 가정, PASS/FAIL/NOT RUN/수정 후 미검증을 포함한다.
포트폴리오에 남길 중요한 작업은 [증거 템플릿](evidence-template.md)을 사용한다.
이미 수집한 로그·측정·검증 결과를 재사용하며 문서 작성을 위해 검사를 반복하지 않는다.
작업 종료·인계 전에 [현재 작업 상태](current-state.md)의 갱신 시각, 기준 커밋/브랜치, 최근 작업 링크,
보존할 로컬 변경, 미완료 문제, 검증 상태와 다음 작업을 갱신한다. 중요한 결정·중단 지점은 확정 시에도 반영한다.
다른 작업의 미해결 항목을 유지하고 이번 작업 검증과 구분한다. 상세 기록은 링크로 남기며 요약 자체를 대화 로그로 늘리지 않는다.
