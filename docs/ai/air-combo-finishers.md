# 공중 밀림·5타 제한·마무리 기술

> 후속 요청에서 시동타를 제외한 후속타 5회로 변경했다. 현재 높이/타수 규칙과 설정은
> [고정 높이 재피격과 시동타 제외](fixed-air-combo.md)를 따른다. 아래는 최초 구현과 검증 기록이다.

## 사용자가 조절하는 곳

`Assets/QuantumUser/Resources/LSDF_GameConfig.asset`을 선택하고 **Air Combo**를 펼친다.

| Inspector 항목 | 기본값 | 의미 |
|---|---|---|
| 공중 피격 밀림 속도 | 약 0.2 | 낮출수록 매 피격 때 덜 밀림. 0.1부터 조율 가능 |
| 공중 피격 밀림 시간 (틱) | 6 | 밀리는 시간. 0이면 일반 공중 밀림 없음 |
| 마무리 날리기 가로 속도 | 4 | 5타째/마무리 기술의 날리기 속도 |
| 마무리 날리기 위쪽 속도 | 1.5 | 날리기 직후 위로 향하는 속도 |
| 마무리 착지 후 회복 (틱) | 24 | 착지 후 추가타와 조작을 막는 회복 시간 |

기본 60Hz에서 6틱은 0.1초, 24틱은 0.4초다. 수치는 월드 단위다.
`Hit.ForceBack`은 기존 지상 피격/가드 반응에 쓰인다. 공중 밀림은 위의 별도 설정이 제어한다.
기존의 중력·Drag 에셋 원본은 수정하지 않는다.

마무리 기술은 `Assets/QuantumUser/Resources/LSDF_Animator Assets/` 아래 해당 기술의
`... Window Event.asset`을 선택해 **Hit → 콤보 마무리**를 켠다.
다단 기술은 **First Hit → Hit** / **Second Hit → Hit** 등 각 타격 정의에서 선택한다.
예를 들어 마지막 타만 켜면 앞 타격은 일반 공중 콤보로 연결되고 마지막 타격이 맞을 때 종료한다.
사용자가 선택할 수 있도록 기존 기술 에셋에 임의로 체크하지 않았다.

## 완료 조건과 타수의 의미

- 띄우는 시동타를 1타로 포함해, 한 공중 콤보의 실제 피격은 최대 5회다. 시동타 이후 후속타는 4회다.
- 실제 피격된 히트박스마다 센다. 다단 기술은 각 타가 별도 타수다. 가드·회피·패링은 타수를 늘리지 않는다.
- 5번째 실제 피격은 피해를 한 번 적용하고 바로 멀리 날린다. 같은 틱의 다른 히트박스도 추가 피격을 만들 수 없다.
- `콤보 마무리`는 순번과 무관하게 같은 날리기를 만든다. 지상 첫 타로 적중해도 적용한다.
  가드/회피된 기술은 마무리를 발생시키지 않는다.
- 날아가는 동안과 착지 후 회복 동안 추가 피해·경직·피격 효과·카운터 줌을 막는다.
  벽에서는 물리 충돌을 유지하며 추가 벽꽝 반응으로 이 잠금을 풀지 않는다.
- 회복 종료/일반 착지의 Rising/KO/라운드 초기화에서 공중 상태와 카운트를 정리한다.
  기존 공중 콤보가 벽콤으로 이어질 때는 카운트를 유지한다.
- 기존 `LSDF_Player.hitCount`는 애니메이션 기반 피해 보정값으로 보존했다.
  새 `LSDF_AirCombo.HitCount`가 실제 피격 횟수를 센다. 기존 보정의 피해 0인 구간도 실제 피격이면 1타다.

## Quantum 구현 경계와 타이밍

타수, phase, 가로 속도, 밀림 종료 틱, 착지 회복 종료 틱은 모두 QTN `LSDF_AirCombo`에 저장한다.
`BlownAway → Recovering → Inactive`를 기존 PlayerSystem에서 진행한다. 시스템 순서를 변경하거나
새 시스템을 중복 등록하지 않았다. 일반/카운터 실제 피격 경로가 동일한 카운트 함수를 사용한다.
런처가 맞은 시점부터 운동 상태를 잡으므로 첫 Air 애니메이션 진입 이전에도 타수를 정확히 센다.
히트박스 생성/물리 관측/파괴 순서는 유지하되, 공중 모션과 종료 시점은 의도적으로 달라진다.

불변 설정은 GameConfig와 `LSDFSingleHitDefinition.ComboFinisher`에 두고 히트박스 생성 때 QTN payload에 복사한다.
시뮬레이션 중 공유 Window Event나 설정 원본에 상태를 쓰지 않는다.
QTN 컴포넌트와 히트박스 직렬화가 바뀌므로 매칭 버전을 `lsdf-loadout-v6-air-combo`로 올려
이전 실행 파일과 같은 방에 들어가지 않도록 한다. 두 클라이언트는 같은 코드·설정·에셋 DB로 실행해야 한다.

## 최종 검증

구현 완료 후 한 차례에 정적 정책/생성물/Unity 컴파일/공중 모션 단위/종료 단위/관련 전투 회귀/
실제 Photon 두 클라이언트·기록 입력 재생·Frame 저장 복원을 묶는다.
온라인 종료 fixture는 세션 시작 전에 체공을 90틱, 일반 밀림을 0으로 고정하여 타수 규칙을 관측한다.
Law 어퍼는 일반타, Death Fist는 마무리로 고정하며 세션 종료 후 원래 설정을 복구한다. 파일로 저장하지 않는다.
이 fixture의 통과는 기본 체공시간에서 모든 기술이 5타 연결된다는 뜻이 아니다.

결과는 `evidence/air-combo-finishers-validation.json`에 기록한다. 이전 체공 작업의 컴파일 실패 기록은
`air-combo-hover.md`에 보존한다. 최종 화면 타격감, 독립 빌드/다른 플랫폼, 강제 네트워크 지연 rollback은 별도다.

운영 코드와 설정은 최종 검사 후 바꾸지 않았다. 사용자 방침에 따라 검사를 재실행하지 않았고,
전체 상태는 **테스트 수정 후 미검증**이다. 작성한 테스트를 통과한 결과로 표현하지 않는다.
