# 공중 콤보 상승·체공·낙하

> 현재 재타격은 [고정 높이 재피격과 시동타 제외](fixed-air-combo.md) 방식이다.
> 아래는 최초 상승·체공 구현 당시의 동작과 검증 기록이다.

## 완료할 사용자 동작

런처로 뜬 캐릭터가 공격하기 쉬운 높이에 잠시 머물고 떨어진다. 공중에서 다시 맞으면 낙하를 끊고
작게 다시 떠서 다음 공격을 연결할 수 있다. 연타로 계속 위로 벗어나지 않도록 높이 상한을 둔다.

설정은 `Assets/QuantumUser/Resources/LSDF_GameConfig.asset`의 **공중 콤보 → Air Combo**에 있다.
위치는 캐릭터 원점의 월드 Y 높이이며, 최초 공중 피격 위치를 기준으로 한다.

| 설정 | 기본값 | 조절 결과 |
|---|---|---|
| 처음 뜨는 높이 | 약 0.30 | 첫 런처 후 머물 높이 |
| 처음 상승 시간 (틱) | 12 | 낮추면 더 빠르게 뜸 |
| 처음 머무는 시간 (틱) | 24 | 늘리면 첫 후속 공격 연결 시간이 늘어남 |
| 재타격 최소 높이 | 0.25 | 낮게 떨어진 대상을 다시 올릴 높이 |
| 재타격 추가 상승 높이 | 약 0.05 | 이미 떠 있는 대상의 작은 재상승 폭 |
| 재타격 상승 시간 (틱) | 6 | 재타격 후 상승 속도 |
| 재타격 머무는 시간 (틱) | 12 | 다음 콤보 연결 여유 |
| 최대 공중 높이 | 약 0.35 | 연타 중 목표 높이 상한 |

기본 60Hz에서 12틱 = 0.2초, 24틱 = 0.4초다. 체공 시간은 **상승을 마친 뒤부터** 센다.
처음 뜨는 높이보다 최대 높이를 작게 설정하면 최대 높이로 제한한다. 시간은 상승 1~600틱,
체공 0~600틱으로 보정하며 0틱 체공이면 상승 직후 낙하한다. 고정소수점 특성상 높이는 근삿값이다.
기본값은 시작점이며 게임 화면에서의 최종 타격감 조율은 사용자 평가가 필요하다.

## 이전 동작과 이번 변경

- 이전 `AirWindowEvent.Execute`는 애니메이션 10프레임까지 Y 속도를 1 또는 0.5,
  이후 30프레임까지 0.5로 매 틱 덮어썼다. 정해진 위치에서 머무는 구간이 없었다.
- 이번에는 동일한 PlayerSystem 위치에서 `Rising → Hovering → Falling`을 진행한다.
  상승은 남은 높이와 틱으로 Y 속도를 정하며, 설치된 PhysicsBody2D의 Drag를 보정한다.
  체공 중에는 Y 속도와 해당 몸체의 중력을 0으로 두고, 낙하할 때 저장한 중력 배율로 복원한다.
- 공중 재타격은 실제 일반 피격 경로에서 목표 높이와 남은 시간을 갱신한다.
  Air 애니메이션이 자기 자신으로 다시 전환돼도 이를 최초 런처로 중복 초기화하지 않는다.
- 기존 `YZero` Animator 전환은 체공 중 속도가 0이라는 이유로 일어나면 안 된다.
  따라서 상승·체공 중에는 막고, 낙하 후 실제 지면 접촉 때 기존 Rising 전환을 허용한다.
- 수평 속도·Drag·일반 점프·런처 피해·기존 공중 hitCount 및 데미지 보정은 이 작업에서 바꾸지 않는다.
  공격 시작/히트박스 생성/충돌/파괴 순서와 시스템 등록도 유지한다.
  실제 공중 궤적과 착지 타이밍, 후속 공격이 닿는 시점은 의도적으로 달라진다.
- 최초 발동 높이, 목표 높이, phase, 상승/체공 종료 틱, 원래 중력 배율은 새 `LSDF_AirCombo` 컴포넌트로
  Frame에 저장한다. 공유 Window Event와 시스템 필드에는 플레이어별 상태를 두지 않는다.
- 벽 충돌, Rising 진입, KO/라운드 포즈, isAir 해제 시 중력을 복원하고 컴포넌트 값을 초기화한다.
  물리 몸체가 잠든 경우 재상승·낙하 시 깨운다. 캐릭터 에셋의 원래 중력 배율이 1이 아니어도 보존한다.
- 기존 `.meta`, 설정 에셋 GUID, Animator 상태/변수, 프리팹 참조를 유지한다.
  새 QTN은 설치된 `Tools/Quantum/CodeGen/Run Qtn CodeGen`으로 생성하며 생성 코드를 직접 편집하지 않는다.

| 공중 모션 단위 / 관련 회귀 | NOT RUN | 컴파일 실패로 테스트 job을 시작하지 않음 |
| Photon 두 클라이언트 / 체크섬 / 재생·Frame 복원 | NOT RUN | 같은 이유로 실행하지 않음 |

FP 비교는 `Assert.IsTrue(a < b)` 등 고정소수점 비교 연산 결과를 검사하는 방식으로 수정했다.
운영 코드와 설정은 이 실패 후 수정하지 않았다. 사용자 방침에 따라 검사를 재실행하지 않았으며
전체 결과는 **테스트 수정 후 미검증**이다. 기존 메뉴 테스트의 `AvailableScenes` 사용 중단 경고 3건도 콘솔에 있었다.

새 온라인 시나리오에는 1P/2P를 번갈아 띄워 체공·재타격·낙하·착지/중력 복원 관찰,
확정 체크섬 비교, 입력 재생 2회, 체공 중 Frame 저장·복원 후 재시뮬레이션을 작성했다.
이들은 작성만 완료했으며 통과 근거는 아직 없다. 독립 빌드/다른 플랫폼, 실제 지연 유발 rollback과
수동 타격감 평가도 NOT RUN이다. 결과와 수정 전 소스 스냅샷은
[`evidence/air-combo-hover-validation.json`](evidence/air-combo-hover-validation.json)에 남긴다.

기존 사용자 변경인 `LSDF_Player2TestInput.asset`과 IDE 생성 파일은 보존한다.
